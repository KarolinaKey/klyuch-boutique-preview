# КЛЮЧ — новая витрина

Отдельная тестовая версия магазина: 89 букетов с ценами и 10 корзин по запросу, фильтры, карточки с ракурсами, корзина, доставка/самовывоз, резюме заказа и подготовка сообщения флористу.

**Просмотр не принимает заказы и оплату.** Данные формы не отправляются; в браузере сохраняется только корзина. Подключений к боевой аналитике, CRM и платёжному API нет.

## Локально

Node.js 20+: `node serve.mjs`, открыть http://127.0.0.1:4173 . Проверки: `npm test`.

## Данные

Каталог перенесён из предоставленного владельцем KeyFlow, ветка deploy/railway-storefront. Сохранены идентификаторы, названия, цены и изображения. Текущие наличие, состав, размеры и цены перед настоящим запуском требуют подтверждения. Часть фотографий ранее обрабатывалась генеративно — необходима сверка с оригиналами. Корзины не имеют утверждённых цен, поэтому доступны только по запросу.

## Структура

- index.html — главная;
- catalog.html, catalog-data.js — каталог;
- checkout.html — безопасный просмотр заказа;
- info.html — информация;
- app.js — интерфейс; logic.js — проверяемая логика;
- style.css, ./ — оформление и локальные ресурсы.

GitHub Pages использует самостоятельную публикационную копию с файлами ресурсов в корне; пути адаптированы автоматически. Приватные исходники прежнего backend, архивы и данные клиентов в публичный репозиторий не включаются. Существующий сайт и исходный приватный репозиторий не изменены.

## Перед боевым запуском

Подтвердить товарные данные и доставку, контакты флориста и документы. Подключить серверную проверку цен, сохранение заказов, уведомления менеджеру, изолированное тестирование платежей и статусов. Реальные платежи и перенос домена выполняются отдельно после согласования.

## Тест дополнений

В корзине — ваза, упаковка, подарок и открытка. Товары и цены условные, помечены как примеры. Дополнения необязательны, максимум по одному каждого вида; исчезают при удалении последнего букета. Выбор и итог сохраняются между страницами. Это проверка интерфейса, не измерение продаж.
